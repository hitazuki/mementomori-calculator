# AI 角色能力评分 v5

当前为 `ai-capability-v5`，134 名角色、804 项评审。评分是固定基础面板下的 AI 编辑判断，用于能力与作用比较，独立于讨伐模拟器，不代表实际同养成战斗排名。原文、计算输入、旧新分与修正都可追溯。

## 六维与统一档位

六维：单体输出、群体输出、自身生存、团队防护、进攻辅助、行动干扰；各 0–10 分，不设总分。0 无该类贡献，1–2 微弱，3–4 有限，5–6 有效，7–8 突出，9–10 全池顶尖候选。成熟强度决定基础档位，持续时间、消耗、补充、启动及覆盖共同决定最终档位。

**属性要求按合理配队满足，不直接扣分。** 最高攻击/速度、其他友军、邻位、存活人数仍影响实际受益人数。敌人属性、敌方驱散、敌人弱化等条件不是自由配队就能保证。治疗提供续航，不是额外防御乘区。

|维度|评价内容|避免混淆|
|---|---|---|
|单体输出|一名敌人下，技能倍率、段数、自增益、完整循环每行动收益|击杀续击不能视为对单个存活敌人无限攻击|
|群体输出|五名敌人的总收益与实际分布|定点十连击不是十次全体攻击|
|自身生存|短期保命、抗致命容量、有效续航|一次性盾的有效期不是补盾频率|
|团队防护|友军生命/盾/治疗/免疫，敌方减攻、脱力、输出降低|脱力独立于加攻减攻；输出降低属于增伤减伤区|
|进攻辅助|攻击、暴率、暴伤、速度、减冷却、减防、易伤、驱散、减疗、增益免疫|不治和增益免疫不是行动控制|
|行动干扰|晕厥、沉默、沉睡、禁锢、减速、迟缓|净化不是对敌控制；挑衅主要是团队防护|

辅助/控制先按成熟收益、覆盖人数与原文命中概率分档：小幅单目标或一次性低概率通常 1–4；中等幅度单目标、概率多目标通常 5–6；强单目标或有效多目标 7–8；显著乘算增益、强群体保护/控制且覆盖可靠才是 9–10 候选。再检查持续/CD、受益选择、启动与重触发。不能仅凭一个高数值或技能关键词自动赋分。

## 基础面板和最终输出

统一设基础攻击 1、生命 3、专长属性 0.25、防御/攻击 0.5、暴率 50%、额外暴伤 50%；两路有效防御/防御定数均 1，穿透/穿透定数均 1。它们是明确的比较假设，不是游戏角色真实成长。最高专武的已确认攻击、生命、防御、暴伤百分比加入相应区；固定穿透以 Lv500 的防御穿透定数 1725、物魔穿透定数 16660 换算。命中/抗暴评级、耐力派生等未确认换算不假造固定最终倍率，排除项逐角色保存。

攻击伤害 = 技能系数 × 段数 × 实际目标数 × 当前攻击 × 暴击期望 × 防御通过率 × 物魔防御通过率 × (1 + 增伤)。同区先相加，跨区相乘，暴率封顶。标准不带角色增益的 100% 攻击普攻伤害为 0.3125，内部以它作为最终伤害比较单位。

每条路径：`1 / (1 + 防御比 × (1 - 减防) × (1 + 基础穿透比) / (1 + 基础穿透比 × (1 + 穿透增幅)))`。两路分别计算。来源攻击/防御转攻用单次快照，不递归增加自身来源；逐段增益只影响后续段数；互斥状态不能拼最高值。

保存单敌、五敌下各技能直接与延迟伤害、各段乘区、两主动总量、完整循环每行动收益。冷却循环按自身行动推演；敌方行动、控制及速度不假装已经模拟。零 CD 但仅 8 回合的变身另列到期后循环；周期强化普攻只在真实补充频率内减 CD。

单体成熟基础档位的每行动基准普攻等效下界依次为：`0.1 / 1.5 / 3 / 5 / 8 / 12 / 18 / 26 / 38 / 55`，分别进入 1–10 档。群体先按同一量尺看五目标总伤害，再作分布修正：随机 n 段在五人场上的期望覆盖为 `5×(1−0.8^n)`，定点连击覆盖 1 人；以全体覆盖为满额，单一目标不赋群攻分。这个覆盖修正是统一编辑尺度，不是游戏伤害公式。

成熟后的高倍率不能消除启动成本。需要反复储备 20 暴击、外部驱散解锁或第20回合成长等，在 `decisions.mjs` 中明确降档及理由。分数按基础档、分布修正、持续/成长修正可重现；不从旧分数反推解释。

## 特殊与延迟伤害

- 力量/魔力/战技直接伤害使用专长属性基准；不额外套攻击、暴击、双防和未经确认的增伤区。
- 生命伤害使用自身或目标对应生命：黛安为自身最大生命35%自损后100%转伤；圣夜托波波为 `min(目标当前生命20%, 自身当前攻击500%)`。
- 承伤反击记录真实基数公式与敏感性。菲雅的20回合累计承伤使用 0/1/2/4 倍自身最大生命样本，中段仅作比较，不宣称已经模拟20回合来伤。
- 当前生命毒按每次剩余生命递减，不直接用初始生命×次数。延迟攻击伤害不重复乘暴击、攻击或防御；侵蚀基于已结算伤害，不把伤害源再结算一次。
- 延迟伤害比较样本假定持续期内目标存活且未净化。实际提前击杀、净化、免疫和技能覆盖分配有不确定性，原文条件与模型假设保留在记录里。
- 共鸣的队友伤害计进攻辅助；复制、夺取、反伤没有可靠外部基数时保留明确限制，不生成任意无限上限。

## 生存、时间和补充

固定攻击:生命=1:3，因此300%攻击盾约等于100%基础生命盾。生命+100%相当于容量翻倍；没有其他同区生命时，粗略等价独立50%阻绝的容量收益。

有限容量按 `(生命 + 当前剩余盾) × 防御路 × 物魔路 × 增伤减伤路 × 独立阻绝` 比较。常规来伤同时列0%和25%增伤；100%增伤只作压力测试，不用它普遍压低减伤。物理、魔法分别比较。普通生命和防御百分比同区累加。专长盾使用专长数值，不能误当攻击盾。

沿用容量锚点：稳定约2倍通常6分、2.5倍约7分、3–4倍约8分、4倍以上进入9分候选；10分需显著容量和可靠持续/保命共同成立。有限容量基档采用普通场景，特殊不死、阈值截断、屏障、闪避、复活另作基础候选，不能算无限容量。物理单路强不等于对魔法也强。

每名角色的防护记录包含：生效时点/持续、消耗条件、刷新/补充、冷却/次数上限、到期后能力。组合记录保存在 `lifecycle.txt`，逐状态有限乘区保存在 `survival-inputs.mjs`。开局、成熟、耗尽/空窗、第7回合后以及额外到期点分别核对，不将不同阶段相乘。

- **不死/免疫**：按持续和再触发评价。阿姆蕾特仅一次3回合不死，结束可能仍残血，不等于顶级持续生存；夏日阿姆还要考虑1血受击消耗持续、4行动间隔及第33回合停止。
- **一次性盾**：只增加当时抗爆发；提前耗尽或到期都失去保护，长有效期不等于每回合恢复。
- **周期盾**：区分补发、覆盖、只延长持续、可叠加。哀音1700%是专长盾，每1行动补；梅尔林第13回合停止补盾，不能同时套第15回合满层攻击生成新盾。
- **治疗/吸血**：有效回复=`min(当时缺失生命, 原回复×回复修正)`，扣除溢出/减疗/触发不足；致命后无法触发的回复为0。回复后的生命继续享受防护，但不提高该次致命伤门槛。吸血取实际已造成伤害。
- **屏障**：按每次伤害的消耗条件、层数、补发节奏；同回合多段可耗尽，不能把两层当两回合。

最终生存是三项合并的编辑分。短强长弱可多档修正，但必须保留具体原因，例如史黛拉一次800%盾6回合、辉夜一次1000%盾4回合、朝日第11回合全套保护到期。倍率更高但分数更低的比较逐对保存容量、分数和双方的持续/回复/条件差别。

## 成长记录

计数类记录初始、每次增量、上限、总事件数、频率、重置。总事件数为 `ceil((上限−初始)/每次增量)`；自损两次、连续恢复三次按事件逐次计数，不按一次技能只算一次。没有已知事件频率时不强行换回合。

回合/行动成长记录启动、成熟、到期；属性满足不等于计数已满。无限成长无虚构上限，托波波明确选第3次S1参考；身影一类消耗资源不假称增长至满层。分数依据应说明“需要累计多少次”“第三次S1”“第7回合才开启”等关键限制。

## 文件、更新和审核

|文件|用途|
|---|---|
|`v5/attack-inputs.txt`、`decisions.mjs`、`secondary-inputs.mjs`|AI逐角色合并的技能倍率、自增益、特殊伤害和评分修正|
|`v5/growth.txt`、`lifecycle.txt`、`survival-inputs.mjs`|成长、补充/消耗与状态乘区|
|`v5/auxiliary-notes.mjs`|辅助/控制的修订依据|
|`v5/v4-reviews.txt`|不可覆盖的v4原始评审快照|
|`v5/review.json`、`changes.md`、`inversions.json`|全池六维旧新分、基础档/修正、最终参考及倒挂原因|
|`reviews.txt`、`survival-profiles.json`|发布输入；由v5重评打包产生|
|`public/data/character-ratings/*.json`|每个角色六维、原文证据、内部评审与计算|
|`index.json`、`status.json`|列表排序和资料是否需要复核|

旧 `offense-profiles.json` 与 `characterOffense.js` 是v3/v4“仅自增益边际收益”历史参照，不再用于v5评分或页面发布。不要从其旧快照最大值直接生成新分数。

流程：读取目标全部技能等级、三档专武及最高专武属性 → 合并机制/目标/时机 → 写明确数值与生命周期 → 重算成熟和到期状态 → 同池六维分档 → 检查所有倒挂与具体限制 → 打包审计。更新现有角色时先改作者输入，而非手改生成JSON。

```text
node scripts/review_character_ratings_v5.mjs
node scripts/build_character_ratings.mjs
node scripts/audit_character_ratings.mjs
npm run build
```

这次全池重评脚本以v4快照做旧新对照。新角色须先建立独立的初始完整评审，再增加同样格式的v5输入和原文基线；不能把缺失旧分伪装成0。若扩大角色池，更新全池数量校验。MB更新后GitHub Action只标记待复核，不自动调用AI，也不能直接刷新哈希消除待复核。

页面只保留雷达、分数、简短依据及关键限制，不恢复计算参照面板。列表仅加载轻量索引；详情按需加载当前角色的记录。

剩余限制见 [v5/limitations.md](v5/limitations.md)；全池变化见 [v5/changes.md](v5/changes.md)。结构测试保证计算和数据一致，不证明所有文本机制已经由实战日志证实。
