# AI 角色能力评分 v1

评分与讨伐配置、编译器、运行时完全独立。仅共享角色概览中的 MB 原文和专武资料，不修改讨伐结果。

## 评分口径

初版由 Codex / GPT-6 逐个阅读 134 名角色的全部技能等级、专武技能及最高阶段专武属性后，直接撰写 804 项评分及依据。并非关键词计数算法，也不是战斗模拟或日志验证。原始评审保存在 reviews.txt，脚本只进行封装和校验，不推断分数。

统一取可获得的满级技能、最高阶段专武；无专武的角色不补造专武。相同养成预算，不计秘仪等账号加成。兼顾前期贡献与持续成长，条件较重的后期上限不会等同开局能力。不输出胜率、精确伤害或综合强度排名。

六维：
- 单体输出：对单一目标的主动/普攻伤害、追击、穿透、自增伤和启动条件。
- 群体输出：对多名敌人的总伤害、覆盖范围、持续伤害；随机连击与真正全体攻击区别评估。
- 自身生存：自身减伤、阻绝、护盾、生命、回复、免疫、复活；自损和保护间隔降低稳定性。
- 团队保护：对其他友军的治疗、生命、防护、净化、代承伤；自身效果不计入此轴。
- 增益削弱：提高友军进攻效率或压低敌方能力的加成、减防、易伤、驱散、冷却、速度等。
- 控制干扰：晕厥、沉默、睡眠、迟缓及功能限制；减疗、增益免疫不等于损失整次行动。
一项效果可影响多个不同结果，但各轴并列呈现，绝不相加为总分。

固定序数档位（不是等距数值模型）：
0 无明显专长贡献（并非角色实际伤害为零）；1 微弱；2 有限；3 明确有效；4 突出；5 该角色的强项。
5 分不是“全角色最强”。评分主观性和场景依赖通过明确说明及具体条件保留，不编造数值置信度。
锚点示例：原版科迪的单体输出、梅琳的辅助、圣剑福尔蒂娜的团队保护、雪幻露娜琳德的控制为各自5档参考；均需阅读其条件。不能将免疫Boss环境套用到控制评分。

## 数据与发布

- reviews.txt：每行 ID | 六个分数 | 六条中文理由 | 条件说明。
- public/data/character-ratings/<ID>.json：逐角色按需加载的发布文件。保留分数、解释、模型标识、评估日期、量表版本、五语言来源 SHA-256、当时的中文技能/专武原文快照。
- S1/S2/P1/P2 等标识引用该角色概览的技能槽位；W 引用全部专武阶段；stats 保留基础速度和最高阶段专武被动属性。没有专属机制的零分轴也可通过文件中的完整快照复核。
- node scripts/build_character_ratings.mjs 只封装既有 AI 评审。来源发生变化时拒绝刷新哈希。必须实际重新阅读对应角色、修订评审后，显式使用 --reviewed=ID,ID；允许重新评审后维持原分数。
- 新增角色没有评审时封装报错，避免伪造完整覆盖。
- node scripts/audit_character_ratings.mjs 检测源变更/新角色，输出 status.json 中的待评估/待复核名单。Master Data Actions 自动运行此检查，不调用 AI、不改旧分数、不把旧评估日期更新为当天。
- 浏览器独立核验当前语言的来源哈希，资料变化显示旧版待复核。新角色 404 显示待评估；请求失败显示重试；切换角色终止旧请求。
- 初版依据和存档原文为简体中文；标题、六维名称和状态有五语言文案，并明确标注依据语言。
- 雷达图使用原生 SVG，无额外图表运行时依赖，提供文本分数和键盘可操作的维度按钮。

## 后续更新

AI只对有变化的角色重新评分，沿用固定量表与锚点，保留对应技能依据和条件。检查明显跨档变化及描述相互冲突；分数变化通过 Git diff 审阅。模型自报置信度和自己生成的测试预期都不能作为实战准确性证据。讨伐继续按既有日志和回归流程独立维护。
