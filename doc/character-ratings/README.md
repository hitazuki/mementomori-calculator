# AI 角色能力评分 v2

评分与讨伐配置、编译器、运行时完全独立，仅共享角色概览中的 MB 原文和专武资料，不改变讨伐结果。

## 评分口径

134 名角色统一按满级技能、最高阶段专武比较。初版已逐个阅读全部技能与专武；v2 对全部角色重新进行 0–10 整数档校准，并重划功能归属、复核受影响原文、编写主要机制标签。不是将旧分数乘二。分数、804 条逐轴依据、条件和标签保存在 reviews.txt。

这是 AI 文本评审，不是战斗模拟或逐词条精确收益计算。倍率、覆盖人数、概率、持续时间、速度、冷却、启动回合、属性限制、自损和面板来源用于定性比较；不能用词条存在或百分比大直接生成分数。无专武不补造，不计账号秘仪。互斥条件不同时按上限计算。

## 六个作用维度

| 维度 | 纳入范围 | 边界 |
|---|---|---|
| 单体输出 | 单目标伤害、追击、自增伤、直接及持续伤害 | 条件与启动折价，不同伤害基准不直接相加 |
| 群体输出 | 多目标伤害、覆盖、扩散、持续伤害 | 随机多段不等同每个目标完整连击 |
| 自身生存 | 自身防御、护盾、减伤、阻绝、免疫、复活、回复 | 反伤不等于减伤；自身受益不计团队防护 |
| 团队防护 | 友军防御、治疗、净化、代承伤，以及降低敌方攻击、输出、暴击、贯通、命中 | 脱力、输出下降、减攻均在此，但乘区不同 |
| 进攻辅助 | 友军加攻、暴击、命中、加速、减冷却，以及敌方减防、易伤、驱散、增益免疫、回复抑制 | 减疗不是行动控制；自身增益主要计输出 |
| 行动干扰 | 晕厥、沉默、沉睡、禁锢、减速、冷却恢复延缓 | 减速与硬控分档；挑衅主要计防护；复制不默认硬控 |

同一效果可以有不同方面的真实贡献，例如吸攻同时改善自身输出和团队防护。但不能仅因效果是异常就给进攻辅助和行动干扰加分。六轴不求和，不输出综合排名。

## 统一 10 分标准

| 分数 | 跨角色含义 |
|---|---|
| 0 | 无该类有效贡献 |
| 1–2 | 微弱、附带贡献 |
| 3–4 | 有限，或覆盖及条件苛刻 |
| 5–6 | 有效，能承担部分职责 |
| 7–8 | 突出，能承担主要职责 |
| 9–10 | 当前角色池的顶尖能力参考，仍有条件 |

分数是序数判断，不代表等距收益、胜率或小数级精度。同档中稳定性、覆盖和启动更优者优先上档；不为增加区分度随意分配奇数。9–10 不保证所有场景都更强，也不是该角色自身的最佳能力就能获得满分。

参照：原版科迪单体 9，梅琳进攻辅助 9，圣剑福尔蒂娜团队防护 10，雪幻露娜琳德行动干扰 9。福尔蒂娜受来源面板与轮转影响，露娜琳德受暴击、冷却和免疫限制。基础攻击角色保留微弱输出，不用零分表示没有攻击行为。

## 乘区边界

- 加攻减攻属于攻击乘区。来源面板加攻需比较来源与受益者面板，不等于受益者同百分比增幅。
- 脱力是独立于加攻减攻的乘算因素，不能按百分点相减。
- 输出伤害下降属于增伤减伤乘区。露莎卡的该效果、尤里卡的打叉叉不等于脱力，也不能直接当成固定比例最终减伤。输出提升、承受伤害变化同样标识增伤减伤乘区；标签不替代具体叠加规则。
- 减防、贯通收益随敌防、贯通、等级非线性变化。80%减防不是固定80%增伤。
- 暴伤考虑暴击率、原有倍率与相关减免，不默认必暴。
- 阻绝、伤害截断、屏障与减伤分开标注。

以上用于约束评审，本版没有新增场景模拟器或宣称逐词条已完成精确收益计算。脱力和输出下降乘区依据为本次用户明确纠正，MB 原文快照另行保留。

## 机制标签

标签描述效果类型，雷达描述实际作用，二者不一一对应。四组为增益、异常、恢复、其他机制。恢复及驱散、复制、冷却等另列。分类是图鉴编辑标签，不是引擎状态枚举。

每个标签由评审者显式编写并引用 S1/S2/P1/P2/W/stats，不通过关键词生成。标签是主要机制摘要，并非完整建模清单，也不表示无条件生效。点击标签可在原文区域核对目标、数值与条件；作用于自身还是友军，以原文及评分理由为准。

## 数据与更新

- reviews.txt：每行 ID | 六个分数 | 六条理由 | 条件 | 标签。标签语法为 key@S1+W,key@P1。
- src/utils/characterRatings.js：v2 量表、10 分上限、标签字典与校验。
- public/data/character-ratings/ID.json：schemaVersion 2、scaleMax 10，保留日期、模型、量表、五语言来源 SHA-256、中文原文快照及逐标签引用。
- node scripts/build_character_ratings.mjs：只封装评审，不生成分数或标签。源变更必须实际评审后使用 --reviewed=ID,ID；量表升级采用本轮日期，旧评分通过 Git 保留。
- node scripts/audit_character_ratings.mjs：Master Data Actions 检查资料变更与新角色，输出待复核／待评估名单。不调用 AI、不改变分数、不刷新旧日期。
- 浏览器核验当前语言来源哈希，变化显示待复核，缺失显示待评估，失败可重试。
- UI 五语言；理由、标签名称与原文快照暂为简体中文，并明确提示。
- SVG 按 0–10 统一半径绘制，提供文本和键盘操作，数据逐角色按需加载。

后续仅复核变化角色；全池尺度变化需升级量表并重新校准。程序校验只能验证结构和引用完整性，不能证明实战准确性。
