# AI 角色能力评分 v6

当前为 `ai-capability-v6`，134 名角色、938 项评审。评分是固定基础面板下的 AI 编辑判断，用于能力与作用比较，独立于讨伐模拟器，不代表实际同养成战斗排名。原文、计算输入、旧新分与修正都可追溯。

## 七维与统一档位

输出特点标签独立于评分量尺，由已审核的主动技能目标结构生成，并显示S1/S2类型：固定多目标为群攻；随机单体连击在多敌时会分散，单敌时可集中全部次数；两类并存或有明确单敌强化连击分支为单群兼顾。群攻重复多轮不变成单体，普通攻击不参与定位。不得再以“五敌总倍率÷3”与单敌倍率的接近程度判定定位。繁花魔女的两主动均为群攻；普通/夏日/团长科迪和黄昏福尔蒂娜为单群兼顾。

七维：爆发输出、后期输出、爆发防御、持续生存、团队防护、进攻辅助、行动干扰；各 0–10 分，不设总分。0 无该类贡献，1–2 微弱，3–4 有限，5–6 有效，7–8 突出，9–10 全池顶尖候选。成熟强度决定基础档位，持续时间、消耗、补充、启动及覆盖共同决定最终档位。

**属性要求按合理配队满足，不直接扣分。** 最高攻击/速度、其他友军、邻位、存活人数仍影响实际受益人数。敌人属性、敌方驱散、敌人弱化等条件不是自由配队就能保证。治疗提供续航，不是额外防御乘区。

|维度|评价内容|避免混淆|
|---|---|---|
|爆发输出|开局前两次行动及短计数/短回合窗口的直接伤害|首轮与条件强化分开，攻击后叠层不回填，延迟伤害不提前结算|
|后期输出|基础与成熟后的循环每行动收益、关键解锁及到期后的能力|不因启动晚扣后期分；不代表每回合持续造成伤害|
|爆发防御|短时间集中攻击、有限承伤容量、屏障、不死与复活|检查多段消耗与生效时点，不能全部换成无限容量|
|持续生存|保护保持、补盾、治疗与消耗后的能力|一次性盾的有效期不是补盾频率|
|团队防护|友军生命/盾/治疗/免疫，敌方减攻、脱力、输出降低|脱力独立于加攻减攻；输出降低属于增伤减伤区|
|进攻辅助|攻击、暴率、暴伤、速度、减冷却、减防、易伤、驱散、减疗、增益免疫|不治和增益免疫不是行动控制|
|行动干扰|晕厥、沉默、沉睡、禁锢、减速、迟缓|净化不是对敌控制；挑衅主要是团队防护|

辅助/控制先按成熟收益、覆盖人数与原文命中概率分档：小幅单目标或一次性低概率通常 1–4；中等幅度单目标、概率多目标通常 5–6；强单目标或有效多目标 7–8；显著乘算增益、强群体保护/控制且覆盖可靠才是 9–10 候选。再检查持续/CD、受益选择、启动与重触发。不能仅凭一个高数值或技能关键词自动赋分。

## 基础面板和最终输出

统一设基础攻击 1、生命 3、专长属性 0.25、防御/攻击 0.5、暴率 50%、额外暴伤 50%；两路有效防御/防御定数均 1，穿透/穿透定数均 1。它们是明确的比较假设，不是游戏角色真实成长。最高专武的已确认攻击、生命、防御、暴伤百分比加入相应区；固定穿透以 Lv500 的防御穿透定数 1725、物魔穿透定数 16660 换算。命中/抗暴评级、耐力派生等未确认换算不假造固定最终倍率，排除项逐角色保存。

攻击伤害 = 技能系数 × 段数 × 实际目标数 × 当前攻击 × 暴击期望 × 防御通过率 × 物魔防御通过率 × (1 + 增伤)。同区先相加，跨区相乘，暴率封顶。标准不带角色增益的 100% 攻击普攻伤害为 0.3125，内部以它作为最终伤害比较单位。

页面的**等效技能倍率** = 最终伤害 / 0.3125 × 100%，表示在同一无角色自增益基准面板上，需要多大技能系数才会造成相同伤害；不是原始技能文本倍率。适用的加攻、暴伤、减防等已合并。特殊伤害仅折合最终伤害量，并不因此获得攻击/暴击乘区。爆发注明两行动合计，后期注明完整循环每行动；单敌与五敌总计分别标示。

页面的**等效生命**以无额外保护的100%基准生命为单位；最终承伤容量4倍记为400%，不表示角色实际生命面板加成。0%初始增伤下，生命+100%与65%减伤组合为571%等效生命；若另有22%专武生命，同区合计后为634%。完整盾、盾耗尽与不同条件分别记录；不死/屏障不折为无限生命，治疗不抬高单次致命阈值。

每条路径：`1 / (1 + 防御比 × (1 - 减防) × (1 + 基础穿透比) / (1 + 基础穿透比 × (1 + 穿透增幅)))`。两路分别计算。来源攻击/防御转攻用单次快照，不递归增加自身来源；逐段增益只影响后续段数；互斥状态不能拼最高值。

保存单敌、五敌下各技能直接与延迟伤害、各段乘区、两主动总量、完整循环每行动收益。冷却循环按自身行动推演；敌方行动、控制及速度不假装已经模拟。零 CD 但仅 8 回合的变身另列到期后循环；周期强化普攻只在真实补充频率内减 CD。

输出的单敌循环每行动档位下界为 `0.1 / 1.5 / 3 / 5 / 8 / 12 / 18 / 26 / 38 / 55`。爆发按开局两行动总直接伤害除以2，下界为 `0.1 / 2 / 4 / 7 / 11 / 17 / 25 / 37.5 / 55 / 80`。五敌总量使用各自3倍下界比较，取优势定位的分档；既不简单平均单群，也不把五敌总量与单敌直接比较。3倍为统一编辑量尺，非游戏伤害公式。输出特点独立按技能目标结构标示“单体输出／随机连击／群体输出／单群兼顾”，不使用上述评分量尺判定标签。

每名角色保存 lower（基础条件）、opening（首轮自身已发生事件）、mature（成熟循环）、upper（额外有限条件上界）；有短期强化再保存 quick 样本与可达条件。记录的最小/最大仅覆盖已审核条件，不宣称包含未知复制、外援及任意敌方面板的绝对极值。高血增攻与低血加成、一次性强化不拼接。两项输出都保留初始强度下限，不能因为存在成长而抹去已有爆发。

**短计数/短回合计爆发，长计数/晚回合计后期。** 1–4次事件、前1–2回合可达的强化可作为短期候选；超过4次不机械判晚，先检查一次技能能触发多少事件。例如一次多种净化可计5种、两次控制可给10层，一次自损两次就是2个事件。反之，5次普通攻击暴击要至少5次普攻，不能因只有5层便当首轮。每个 quick 输入必须写明事件总数、已知路线与外部条件；未知频率不编造回合。短期候选不等于无条件开局满层。

后期以成熟循环档位为准，等待本身不再扣后期分；一次性到期、资源重复消耗和循环空窗仍能限制收益。神咒伊利亚仅一次8回合解放，到期失去S2窗口，保留具体3档修正和初始下限。爆发取开局与已审核短期条件窗口中的优势分档；敌方控制/足够弱化等条件可降1档，但不能低于开局档位。计数少和初始高分别成立即可有高爆发，不要求两者同时成立。

**成长本身不扣分。** 先比较无成长、首轮和成熟的最终收益，确认成长是在解锁主要强度还是锦上添花，再决定修正。满层晚但开局已接近峰值，不得仅因满层回合数降档。暴击追加攻击需计算有上限的连击期望，并计入攻击前减抗暴等条件；单次爆发与完整循环每行动评分分别说明。佛罗伦斯的对应样本保存在 `output.burst`：标准50%有效基础暴率、S1专武减抗暴成功时首轮96%暴率，已接近10段上限；该条件不延续到下一回合S2。

## 特殊与延迟伤害

- 力量/魔力/战技直接伤害使用专长属性基准；不额外套攻击、暴击、双防和未经确认的增伤区。
- 生命伤害使用自身或目标对应生命：黛安为自身最大生命35%自损后100%转伤；圣夜托波波为 `min(目标当前生命20%, 自身当前攻击500%)`。
- 承伤反击记录真实基数公式与敏感性。菲雅的20回合累计承伤使用 0/1/2/4 倍自身最大生命样本，中段仅作比较，不宣称已经模拟20回合来伤。
- 当前生命毒按每次剩余生命递减，不直接用初始生命×次数。延迟攻击伤害不重复乘暴击、攻击或防御；侵蚀基于已结算伤害，不把伤害源再结算一次。
- 延迟伤害比较样本假定持续期内目标存活且未净化。实际提前击杀、净化、免疫和技能覆盖分配有不确定性，原文条件与模型假设保留在记录里。
- 共鸣的队友伤害计进攻辅助；复制、夺取、反伤没有可靠外部基数时保留明确限制，不生成任意无限上限。

## 生存、时间和补充

### 行动开启防护与速度

仅“爆发防御”使用 `defense-initiative-v1` 开启修正，**爆发输出不按速度加减分**，后手爆发仍按伤害与触发窗口评估。其余五维不因本项修正改变。

逐角色区分战斗/回合开始、受击自动、行动开始、主动技能和行动结束。前两类首次生效不要求先出手；“结束若干次行动后再次触发”也不表示第一次要等若干次行动。需要行动才能获得的部分记录于 `v6/initiative.mjs`，未列角色无此扣分。

有效开启速度 = 基础速度 ×（1 + 开启前已生效的自身速度增幅之和）。计最高技能、专武和合理属性配队下自身提供的加速，不默认外部加速、符石差异或敌方减速。行动中/行动后加速不能回填当前行动顺序；第3/7回合、计数达标、复活后加速和只给予其他友军的加速，不能提前算作开局自身加速。回合开始保护不因低速扣分。

统一编辑参照：有效速度低于3000记2档开启风险，3000至不足3300记1档，3300以上记0档；S2才生效另记1档首轮空窗。合计修正受逐角色已审核的最大扣分和开局保护保底限制，最多扣3分，不会把已有常驻减伤、开局盾或自动复活一起扣除。速度只修正防护可用时点，不改变等效生命、不换算胜率；较快也不表示保证抢在所有敌人之前。

例如玫莉亚开局20%与合理配队专武10%加速合计30%，基础3094折合约4022，可帮助在攻击后补屏障，保留5分；罗莎莉基础2800、须S2后才免疫，8→5；翠西行动前已有大盾和70%减伤，只对尚未开启的防御增益修正，10→9。所有输出分数在本次修订中保持原值。

固定攻击:生命=1:3，因此300%攻击盾约等于100%基础生命盾。生命+100%相当于容量翻倍；没有其他同区生命时，粗略等价独立50%阻绝的容量收益。

有限容量按 `(生命 + 当前剩余盾) × 防御路 × 物魔路 × 增伤减伤路 × 独立阻绝` 比较。常规来伤统一以0%初始增伤评分；25%和100%只作敏感性参照，不参与评分。物理、魔法分别比较。普通生命和防御百分比同区累加。专长盾使用专长数值，不能误当攻击盾。

沿用容量锚点：稳定约2倍通常6分、2.5倍约7分、3–4倍约8分、4倍以上进入9分候选；10分需显著容量和可靠持续/保命共同成立。有限容量基档采用普通场景，特殊不死、阈值截断、屏障、闪避、复活另作基础候选，不能算无限容量。物理单路强不等于对魔法也强。

每名角色的防护记录包含：生效时点/持续、消耗条件、刷新/补充、冷却/次数上限、到期后能力。组合记录保存在 `lifecycle.txt`，逐状态有限乘区保存在 `survival-inputs.mjs`。开局、成熟、耗尽/空窗、第7回合后以及额外到期点分别核对，不将不同阶段相乘。

- **不死/免疫**：按持续和再触发评价。阿姆蕾特仅一次3回合不死，结束可能仍残血，不等于顶级持续生存；夏日阿姆还要考虑1血受击消耗持续、4行动间隔及第33回合停止。
- **一次性盾**：只增加当时抗爆发；提前耗尽或到期都失去保护，长有效期不等于每回合恢复。
- **周期盾**：区分补发、覆盖、只延长持续、可叠加。哀音1700%是专长盾，每1行动补；梅尔林第13回合停止补盾，不能同时套第15回合满层攻击生成新盾。
- **治疗/吸血**：有效回复=`min(当时缺失生命, 原回复×回复修正)`，扣除溢出/减疗/触发不足；致命后无法触发的回复为0。回复后的生命继续享受防护，但不提高该次致命伤门槛。吸血取实际已造成伤害。
- **屏障**：按每次伤害的消耗条件、层数、补发节奏；同回合多段可耗尽，不能把两层当两回合。

爆发防御和持续生存各自评分，不再合并。短强长弱可多档修正，但必须保留具体原因，例如史黛拉一次800%盾6回合、辉夜一次1000%盾4回合、朝日第11回合全套保护到期。倍率更高但分数更低的比较逐对保存容量、分数和双方的持续/回复/条件差别。

## 成长记录

自损/主动恢复的短期状态统一采用**累计4次有效事件**（`v6/four-events.mjs`）。包含自身触发；每主动自损两次计2次，连续恢复三次计3次。蜜拉要求自身收到恢复，与全队恢复事件不同；吸血、再生不擅自算主动恢复。成长上限高于4时只算对应部分，不因尚未叠满便完全不计短期收益；晚回合技能锁仍有效。

此项是逐技能的4事件状态比较，不是声称两主动都能塞进同一4事件连续轨迹。艾谢S1首波按第3次30%加攻、重放按第4次40%加攻逐波计算；S2按4层40%加攻，760%至1520%的血量条件分开列出。低血收尾约9档，高血量保持可达10档；将10作为条件爆发评分时必须显示区间与限制。高端仅是有限上界，不是假定同一目标连续五段始终满血，也不从文本臆造血量插值公式。等效倍率已包含适用的暴率、暴伤、双防/贯通；暴击评级缺乏转换依据时仍排除。

计数类记录初始、每次增量、上限、总事件数、频率、重置。总事件数为 `ceil((上限−初始)/每次增量)`；自损两次、连续恢复三次按事件逐次计数，不按一次技能只算一次。没有已知事件频率时不强行换回合。

回合/行动成长记录启动、成熟、到期；属性满足不等于计数已满。无限成长无虚构上限，托波波明确选第3次S1参考；身影一类消耗资源不假称增长至满层。分数依据应说明“需要累计多少次”“第三次S1”“第7回合才开启”等关键限制。

## 文件、更新和审核

- `v6/stages.mjs`：基础/开局/条件上界参数，成长修正判断，全池两项独立防御分。
- `v6/review.json`：134名角色七维、所有条件样本、成长/持续及原文哈希。
- `v6/changes.md`：旧六维与新七维并列；维度含义不同，不伪造逐项差值。
- `v6/inversions.json`：爆发/后期倍率及两项防御容量更高却分数更低的逐对原因。
- `v5/`：保留原始合并技能参数与历史评审，v6显式覆盖已确认的阶段差异；v5评分脚本不再用于当前发布。
- `reviews.txt` 与 `public/data/character-ratings/`：七维发布输入、按需加载详情与轻量排序索引。

流程：复核完整技能/专武原文 → 更新明确阶段参数与两个防御判断 → 重算所有条件样本 → 校准七维、初始下限与倍率倒挂 → 打包审计。评分独立于讨伐；脚本计算和打包AI维护的参数，不按技能关键词自动赋分。

```text
node scripts/review_character_ratings_v6.mjs
node scripts/build_character_ratings.mjs
node scripts/audit_character_ratings.mjs
npm run build
```
