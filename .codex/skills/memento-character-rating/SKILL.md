# 角色评分 v5

在当前 mmt-calculator 工作区操作，使用 `doc/character-ratings/README.md` 为唯一评分标准。评分与讨伐结构独立，不把粗评输入转换为讨伐可执行机制。

## 先读取

1. README 的当前量表、固定面板、输出与生存档位；`src/utils/characterRatings.js` 的版本、六维及标签字典。
2. `public/data/character-catalog/zh-CN.json` 目标角色的全部技能等级、三个专武效果、最高专武属性。定向读 ID；等级文本需合并追加/替换，不能只看最后一条。
3. `doc/character-ratings/v5/` 中该角色的 attack-inputs、decisions、secondary-inputs、growth、lifecycle、survival-inputs、auxiliary-notes 条目与同定位参照。`review.json`/`changes.md`/`inversions.json` 用于跨角色校准，不从旧分数倒推理由。

## 统一评审流程

1. **确认原文机制**：受益对象、每段时点、数值、持续、消耗、补充、冷却、次数上限、到期后能力。属性按合理配队满足，不额外扣分；选人、站位、存活和敌方条件仍限制实际收益。
2. **组合最终输出**：技能倍率×段数×目标分布×适用的攻击/增伤/暴击/双防通过率。单敌、五敌总收益和完整循环每行动收益都记录。群体分区分随机覆盖与定点连击。特殊直接/生命/承伤/反伤用自己的基准，不能套不适用的攻击、暴击或防御。
3. **核对互斥与逐段生效**：首击生成的攻击增益不回填首击，暴率封顶；击杀加攻不当对单个未死敌人的常态。高血加攻与低血续航、早期吸血与后期倍率、已到期盾与晚期满攻击不能拼最高值。
4. **记录成长**：初始、每次增量、上限、叠满总事件数、事件来源/频率及重置；一次施放可能自损2次或恢复3次。不能把事件数当施放数，也不能把未知频率换成固定回合。回合成长记录启动/成熟/到期，无上限则明确选取有限比较窗口。
5. **组合生存并检查持续性**：有限生命/防御/减伤/阻绝/盾相乘；同时看0%/25%增伤，100%仅压力测试。分别记录短期保命、抗致命容量、有效续航，页面合并为自身生存。不死按持续与再次触发，不算无限容量；一次性长时盾不等于周期盾；屏障按每次消耗，不按层数换固定回合。比较开局、成熟、空窗、第7回合后及额外到期点。
6. **治疗单列**：有效回复=min(缺失生命,原回复×回复修正)，扣溢出/减疗/触发不足；致命后无法回复的取0。回复后的生命继续享受防护，不能提高当次致命门槛。吸血主要续航及反伤反制，不以吸血一项给顶级生存。
7. **六维分档**：成熟收益定基础档，再写持续、可靠性、成长及受益范围的修正。成长本身不扣分：先保存无成长、首轮和成熟的最终收益及差距，区分锦上添花与解锁主要强度；首轮已经高爆发时不得仅因层数多或满层晚降档。暴击追加连击按实际暴率计算有上限的期望段数，攻击前减抗暴须纳入对应技能；不能把其他技能一起视为满暴。爆发峰值与完整循环评分分别解释。辅助/控制按强度、范围、持续/CD和可靠性统一评价。脱力独立于加攻减攻；输出伤害下降在增伤减伤区，二者均主要计团队防护。减疗/增益免疫归进攻辅助；硬控/减速/迟缓归行动干扰。
8. **全池比较**：对倍率高但分数低逐对说明事件总数、有限回合、耗尽后能力、循环效率或覆盖差别。容量、持续、补充都占优却分低且无额外成本时应改分，不只改措辞。大于一档修正保留具体例证。

## 保存、发布和验证

作者输入在 v5 目录，脚本只按显式输入做计算与打包；不从技能关键词自动赋分。不要用旧 `offense-profiles.json` 的最大自增益快照生成v5评分。

保留完整原文引用、来源哈希、旧新六维、基础档、修正原因、成长与补充机制。不能直接刷新哈希消除待复核。新增角色先写完整初始六维评审，再按同一格式补充所有v5作者输入和数量校验；没有旧分就标记首次评审，不当0分。

```text
node scripts/review_character_ratings_v5.mjs
node scripts/build_character_ratings.mjs
node scripts/audit_character_ratings.mjs
npm run build
```

全池脚本的v4快照不可覆盖。新增或源资料改变时必须实际复核之后才打包；GitHub Action仅同步资料和标记stale/pending，不会自动调用AI。检查每个角色六维、发布索引、版本和source hash一致，旧新变化与倒挂都有具体依据。

针对计算改动验证：逐段增益、互斥状态、计数上限、短时不死到期、一次性盾提前耗尽、周期补盾空窗、覆盖旧盾/仅延长持续、多段屏障消耗、治疗溢出和致命后不回血。结构测试不证明实战准确；无法可靠量化的机制写入 `v5/limitations.md`。

页面仅保留雷达、分数和简短理由，明确“持续几回合”“仅一次、不刷新”“累计多少次”，不恢复计算面板。列表使用轻量索引。验证详情及六维排序后，按会话授权提交推送当前分支并检查部署。
