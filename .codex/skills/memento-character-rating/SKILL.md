# 角色评分 v6

以 `doc/character-ratings/README.md` 为唯一量表。当前七维固定为爆发输出、后期输出、爆发防御、持续生存、团队防护、进攻辅助、行动干扰，中文维度名均四字，不设总分。

## 读取与评审

1. 阅读 README、`src/utils/characterRatings.js` 与目标角色全部技能等级、三档专武和最高专武属性。定向查询 `public/data/character-catalog/zh-CN.json`，合并追加/替换描述，不只看最后一级。
2. 查看 `v6/stages.mjs`、`v6/review.json` 及沿用的 v5 技能系数、乘区、成长、生命周期输入。v5/review.json 是历史对照，不能将旧单体/群体分直接改名为爆发/后期。
3. 分别记录基础条件、开局自身已发生事件、成熟与额外有限上界。计数记录初始/增量/上限/总事件数/重置；回合成长记录启动/成熟/到期。未知队友事件频率不编造回合。属性按合理配队满足，其他站位/来源/人数条件仍检查。
4. 爆发分别算首轮前两行动与短期强化窗口：1–4次事件或前1–2回合可达为候选；较多事件若由一次多段/多次恢复/多种净化即可完成，仍可计爆发。每个quick样本记录总次数、来源、频率与外部条件，不宣称必然开局满层。攻击前增益先计，攻击后叠层不回填；未解锁技能、延迟伤害不能提前结算。暴击追加连击计算封顶期望段数。
5. 后期输出按成熟循环分档，长计数/晚回合的等待本身不扣后期分。保留初始高倍率；一次性变身到期、重复消耗资源、长空窗另作修正。少量成长可提高爆发，多量成长主要影响后期；相同角色可以两项都高。
6. 两种输出均保留单敌和五敌结果，使用README中的独立量尺后取优势定位；不能直接比较两者总伤害，不简单平均。页面仅输出特点标签，不增加四个输出维度。
7. 生存统一以0%初始增伤评分，25%/100%只作敏感性参照。生命、防御、减伤、阻绝、盾相乘；常规治疗/吸血不提高单次致命阈值。来源和特殊直接伤害不套未经确认的乘区。
8. 爆发防御和持续生存独立写分。前者检查先行动前、屏障多段消耗、不死/复活和初始盾；后者检查持续/消耗/刷新/冷却/次数/到期/有效回复。长时一次性盾不是持续补盾，短时不死不是无限承伤；治疗扣溢出、减疗和无法存活触发的部分。
9. 辅助/控制按实际受益人数、强度、可靠性、持续/CD评审。脱力独立于加攻减攻；输出下降属于增伤减伤区；减疗/增益免疫归进攻辅助，硬控/减速/迟缓归行动干扰。
10. 对倍率高而分低逐对核对并留理由。不能只为旧分补解释；无法量化的外部队伍、基础评级、事件顺序写入 v6/limitations.md。
11. 页面短依据注明等效技能倍率/等效生命：前者为最终伤害÷基准100%普攻伤害×100%，标明两行动合计或循环每行动、单敌或五敌；后者以100%基准生命为单位，注明完整盾、条件与到期。不把折算结果当原始技能倍率，不把治疗算致命容量。
12. 缺少装备关联时检查主动/被动技能的EquipmentRarityFlags（128/256/512）和官方文本，不能把专武描述行ID当角色ID。库希97三档专武已通过技能MB补齐；被动属性仍缺源表，不补造。同步脚本必须保留这种回退提取。
13. 爆发输出不按速度加减分，允许后手爆发。仅行动开启的爆发防御使用README的先手修正：核对基础速度、自身开局加速（含专武）、生效行动与开局保护保底，维护v6/initiative.mjs。回合开始/受击自动保护不因低速扣分，首次触发不要误用再触发间隔。行动中、晚回合、计数后、复活后或仅给其他友军的加速，不预支为自身首轮速度。等效生命不乘速度；保存修正前后分与原因，验证输出分数不变。
14. 自损/主动恢复的短期状态统一取累计4次有效事件，维护v6/four-events.mjs。按每次而非每个技能计数，核对“自身收到恢复”与“全队触发恢复”的不同；吸血/再生不擅自计主动恢复。未达上限只计4次的实际加成，不预支第7回合解锁。分技能状态参照不冒充同一4事件连续轨迹；艾谢重放按第3/4次分别计算，S2保留随目标剩余生命变化的上下界，不能全段默认满血或只取最低端。区间高端对应的评分须在短依据说明条件。暴率、暴伤、双防下降及贯通计入适用乘区，暴击评级不直接当暴率。

## 保存、验证、发布

输出特点按技能目标结构判定，禁止用单群评分归一化比例贴标签。对N名敌人攻击（N≥2）是群攻（重复发动也仍是群攻）；随机对敌人攻击N次是随机单体连击，多敌时可能分散，不是定点集火。同时存在群攻和单体/随机连击，或有只剩单敌时改为多段的分支，标单群兼顾。只看主动伤害，不因普攻为单体而把所有角色标兼顾。繁花魔女105双群攻为群体输出；科迪27/72/123及黄昏福尔蒂娜151为单群兼顾。标签独立于七维分数。

作者输入由AI复核，脚本只计算明确参数与打包。保存完整原文、source hash、阶段倍率、七个基础档/修正和旧六维对照；不要刷新哈希消除待复核。新角色需全套七维与生命周期，更新数量校验。

```text
node scripts/review_character_ratings_v6.mjs
node scripts/build_character_ratings.mjs
node scripts/audit_character_ratings.mjs
npm run build
```

检查全134名/938项、索引、七轴坐标/排序、五语言、移动端标签；回归首轮暴击连击、后期解锁、一次性/周期盾、提前破盾、不死到期、屏障消耗与治疗溢出。页面只保留雷达、短依据、特点与标签，不恢复计算面板。

GitHub Action仅同步MB并标记stale/pending，不自动评分。评分独立于讨伐结构。按会话授权提交推送当前分支并确认部署。

目标结构补充：核查全部主动技能的各级及专武文本，记录击杀后追击、敌我混选、单敌变招等分支。数值模型未计入的追击仍应体现在定位中，维护 `doc/character-ratings/v6/targeting.mjs` 的原文引用；不得把期望伤害的折算段数当作选敌结构。重生成 `v6/targeting-review.md`，验证改变伤害大小不改变标签，并检查全池分数未被定位修改意外影响。
